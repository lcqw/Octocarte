# Octocarte 0.1.0

## Optional single-song downloads

Full-album downloads remain the default. Set `DOWNLOAD_WHOLE_ALBUM=false` in
`.env` to download only the requested song. This preference applies to every
client connected to the server; omitted settings retain full-album behavior.

Temporary YouTube playback starts independently of the download. ALACarte uses
its existing song-download API and continues to control quality, metadata,
lyrics, library checks and Navidrome scans. Repeated requests are debounced by
song in single-song mode, so two different songs from one album can both download.

The bundled integration token now permits the existing single-song endpoint with
only a song ID. It still cannot change settings, override download preferences,
manage the library or cancel jobs.

## Updating

Keep your `.env`, Compose project name and service volumes. Update your checkout:

```sh
git pull --ff-only
```

Set `OCTOCARTE_VERSION=0.1.0` in `.env`. Keep album downloads by default, or add
`DOWNLOAD_WHOLE_ALBUM=false` to opt into single-song downloads. Then run:

```sh
docker compose pull
docker compose up -d
```

All five images use version `0.1.0`. Update the complete Octocarte stack so its
ALACarte integration accepts the song endpoint. Your independently managed
Navidrome server needs no update for this setting.

Changing the preference does not cancel existing jobs or remove downloaded
music. Client prefetch requests can also trigger acquisition.

## Validation

705 .NET tests and five initialization/configuration tests passed. Authentication
tests cover the song endpoint, restricted request bodies and Origin enforcement.
Controlled HTTP tests passed in album and song modes, covering prompt playback
while download submission is blocked, seeking, repeated requests, search and
handoff to indexed Navidrome files. Live NAS validation of single-song acquisition
remains a follow-up to these automated checks.
