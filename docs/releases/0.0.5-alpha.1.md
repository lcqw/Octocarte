# Octocarte 0.0.5-alpha.1

This prerelease replaces the manual image-import installation with versioned
registry images and normal Docker Compose startup. It includes a full stack and
an add-on example for an existing Navidrome project. Service storage and the
scoped ALACarte integration token are initialized automatically.

Artist photos, Apple-ranked top songs and unattended integration authentication
are included in the prepared ALACarte image. Apple sign-in and all acquisition,
metadata, lyrics, artwork, duplicate handling and scan preferences remain in
ALACarte's existing UI and implementation.

The NAS preview's end-to-end workflow has passed user acceptance. Temporary
YouTube playback was reported to begin in roughly 1–2 seconds. Long-term daily-use
validation continues. Wavio's ALAC prefetching behavior and the unresolved Navic
compatibility report are documented in the client notes.

The release workflow tests fresh installation, the existing-Navidrome add-on,
credential persistence, real catalog features, shared-library indexing and native
range playback. The controlled stream fixture covers asynchronous whole-album
submission and local replacement. This release does not claim universal client
compatibility or exhaustive security coverage.

Requirements: Linux AMD64, Docker Compose v2+, shared music storage and normal
ALACarte account setup. No `latest` image alias is published.

The early NAS bundle used bind-mounted state; this release uses named volumes.
Existing trial installations require a planned state migration rather than
replacing their Compose file in place. Retain their working configuration and
images until that migration is tested.

Source archives and `images.lock.json` accompany the release. Preserve the
upstream licenses and attribution.
